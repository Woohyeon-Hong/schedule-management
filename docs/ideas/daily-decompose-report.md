# 쪼개기+배치 아침 리포트 (가칭)

## Problem Statement
어떻게 하면 캘린더에 덩어리째 올라간 부담스러운 일정을, 사용자가 매번 수동으로 쪼개고 순서를 정하지 않아도, 실행 가능한 단위 + 효율적인 순서로 자동 재구성해서 매일 아침 확인하게 만들 수 있을까?

## Recommended Direction
핵심은 단 하나의 엔진이다: **캘린더 일정을 실행 단위로 쪼개고, 효율적인 순서로 배치한다.**

첫 버전은 앱이나 봇 서버가 아니라, **매일 정해진 시각에 실행되는 읽기 전용 스케줄 루틴**이다. Google Calendar에서 그날 일정을 읽고, 어떤 일정이 "쪼갤 대상(유동적 태스크)"이고 어떤 게 "고정 일정(회의, 예약 등)"인지 판별한 뒤, 유동 태스크만 실행 단위로 분해 + 소요시간을 추정하고, 하루 전체를 효율적인 순서로 재배치해 Slack으로 리포트한다. 쓰기 작업(캘린더 수정)은 하지 않는다.

개인화가 필요한 값(캘린더 ID, Slack 채널/토큰, 리포트 발송 시각, 타임존 등)은 전부 `.env` 파일로 분리한다. 이렇게 하면 코드를 거의 짜지 않고도 검증할 수 있으면서, 동시에 지인들에게 "템플릿 + 자기 값 채우기"만으로 바로 배포할 수 있다 — 검증과 공유 가능성을 한 번에 얻는 선택이다.

실제 개발 단계에서는 쪼개기(decompose)와 배치(arrange)를 **하나의 엔진**이 수행하되(두 단계가 서로의 결과에 영향을 주므로 분리된 서비스로 두면 오히려 조율 비용만 늘어난다), **문서/스펙은 쪼개기와 배치를 별도로 분리**해서 관리한다 — 각 단계의 판단 기준과 실패 조건이 다르기 때문에, 하나의 문서에 섞으면 나중에 어느 쪽 로직을 고치는지 추적하기 어려워진다.

## Key Assumptions to Validate
- [ ] 캘린더 이벤트의 제목/설명만으로 Claude가 의미 있게 쪼갤 수 있다 — 실제 캘린더 이벤트 몇 개로 프롬프트 먼저 테스트해볼 것
- [ ] "효율적인 순서"의 기준을 몇 가지 규칙으로 명문화할 수 있다 — 본인이 실제로 중요시하는 배치 기준(예: 오전 집중 시간대, 이동시간, 데드라인 우선순위) 2-3개를 먼저 텍스트로 적어볼 것
- [ ] 고정 일정과 유동 태스크를 구분하는 판별 로직이 안정적으로 동작한다 — 며칠 돌려보며 오탐(예: 치과 예약을 쪼개려는 경우) 여부 확인
- [ ] `.env` 기반 배포만으로 지인들이 각자 셋업 가능하다 — 지인 1명에게 실제로 셋업시켜보고 막히는 지점 관찰

## MVP Scope
**포함:**
- 매일 지정된 시각에 실행되는 스케줄 루틴 (크론/스케줄 기반, 커스텀 서버 없음)
- Google Calendar에서 당일 일정 읽기 전용 조회
- 일정별 "쪼갤 대상 여부" 판별 → 유동 태스크는 실행 단위 분해 + 소요시간 추정
- 하루 전체(고정 일정 + 분해된 태스크)를 효율적 순서로 재배치
- Slack으로 리포트 전송
- 개인화 값 전부 `.env`로 분리, 지인 배포 가능한 템플릿 형태

**미포함 (아래 Not Doing 참고)**

## Not Doing (and Why)
- **캘린더 쓰기/역방향 등록 (Slack 추상적 할일 → 캘린더 자동 등록)** — 쓰기 작업은 실수 시 되돌리기 어렵다. 읽기 전용으로 먼저 신뢰를 검증한 다음에 결정한다.
- **하루 중 실시간 재조정** — 정적 아침 리포트로 신뢰가 검증되기 전까지는 복잡도를 추가하지 않는다.
- **예측-실측 오차 학습/생산성 코칭** — 초기엔 사용자가 직접 리포트 품질을 판단한다. 데이터가 쌓이면 나중에 고려한다.
- **카카오봇/별도 앱/멀티테넌트 인프라(인증, DB 등)** — 각자 독립 실행 + `.env` 배포로 이번 단계는 충분히 검증 가능하다. 인프라 투자는 코어 로직의 신뢰가 확인된 다음이다.
- **팀/공유 캘린더 조율** — 개인용으로 시작한다. 여러 명의 일정을 엮는 확장은 나중 문제다.

## Open Questions
- 지인 배포 시 Google OAuth(캘린더 접근 권한) 셋업을 각자 어떻게 하게 할지 — 셀프서브 가이드가 필요한가?
- "쪼갤 대상 vs 고정 일정" 판별을 Claude 판단에만 맡길지, 아니면 캘린더 이벤트 제목에 컨벤션(예: `[TASK]` 프리픽스)을 쓰게 할지?
- 배치 기준(에너지 레벨, 데드라인 등)을 사용자가 명시적 규칙으로 프롬프트에 박아넣을지, 아니면 Claude의 기본 판단에 맡길지?

# 등록(register) 스펙

## 목적
Slack 채널에 올라온 메시지를 읽어 캘린더에 일정으로 등록한다. 사용자가 적은 그대로 등록한다 — **쪼개지 않는다.** 쪼개기는 다음 아침 리포트가 [decompose](./decompose.md)로 처리한다.

이 스펙은 리포트 루틴과 별개로, 1시간마다 실행되는 두 번째 루틴이다. **이 저장소에서 캘린더 쓰기가 허용된 유일한 지점이다.**

## 사용하는 config.json 필드
- `slackChannel`: 메시지를 읽을 채널. 리포트를 보내는 채널과 같다.
- `calendarId`: 일정을 등록할 캘린더.
- `timezone`: "내일", "다음주 화요일" 같은 상대 표현을 해석하는 기준 시간대.

## 실행 절차
1. 이 저장소의 `config.json`을 `Read` 툴로 읽는다.
2. `slackChannel`의 **최근 24시간** 메시지를 조회한다.
3. 각 메시지를 아래 순서로 판단한다.
   - **자기 자신이 보낸 메시지는 건너뛴다.** 하루 계획 리포트에는 시각이 가득해서 일정으로 잘못 읽힌다.
   - 리액션이 이미 달려 있으면 건너뛴다 — 처리를 끝냈다는 표시다.
   - 일정을 적은 것으로 읽히지 않으면(잡담, 링크 공유 등) 건너뛰고 리액션도 달지 않는다.
4. 일정으로 읽힌 메시지는 "파싱 규칙"에 따라 캘린더에 등록하고, 리액션과 스레드 회신을 남긴다.

처리 상태는 슬랙 리액션으로만 관리한다. 어디까지 처리했는지 따로 기록하지 않는다.

## 파싱 규칙
- **제목**: 날짜·시각 표현을 걷어낸 나머지를 그대로 쓴다. 남은 부분의 **말투와 단어는 고치지 않는다** — "미용실 ㄱㄱ"을 "미용실 방문"으로 다듬지 않는다. 날짜 표현을 남기면 캘린더에 "모레 4시 반 미용실"이 떠서 나중에 언제인지 알 수 없다.
- **설명**: 메시지에 문장이 둘 이상이면 **첫 문장을 제목, 나머지를 캘린더 이벤트 설명(description)에 넣는다.** 설명을 버리면 다음 아침 리포트가 쪼갤 재료를 잃는다.
- **날짜**: `timezone` 기준으로 해석한다. "내일", "모레", "다음주 화요일"은 실행 시각을 기준으로 계산한다.
  - 요일만 적혀 있으면(`금요일 14시`) **오늘 이후 가장 가까운 그 요일**로 본다. 오늘이 그 요일이면 오늘로 보되, 적힌 시각이 이미 지났으면 다음 주로 넘긴다.
- **시각**: 적혀 있으면 그대로 쓴다. 없으면 **종일 일정으로 등록**한다 — "휴가", "제출 마감일"처럼 시각 없는 일정은 대체로 종일성이다.
- **소요시간**: 적혀 있으면 그대로 쓴다. 시각은 있는데 소요시간이 없으면 **1시간**으로 둔다.
- 메시지에 `[TASK]`가 들어 있으면 제목에 그대로 남긴다. 다음 아침 리포트에서 판별 컨벤션이 작동해 유동 태스크로 쪼개진다.
- **한 메시지에 일정이 여러 개면 전부 등록한다.** 회신에 등록한 것을 모두 나열하고, 리액션은 하나만 단다 — 전부 처리했으므로.

## 처리 후 남기는 것
등록에 성공하면:
- 원본 메시지에 ✅ 리액션을 단다.
- 스레드에 등록 결과를 회신한다. 사용자가 틀린 걸 발견하면 캘린더에서 직접 고친다.

```
등록했습니다
치과 예약 · 3월 5일(수) 15:00-16:00
```

종일 일정으로 등록했을 때는 그 사실을 밝힌다.

```
등록했습니다
여름 휴가 · 8월 3일(월) 종일
```

한 메시지에서 여러 개를 등록했으면 전부 나열한다.

```
등록했습니다
회의 · 7월 31일(금) 10:00-11:00
병원 · 8월 6일(목) 15:00-16:00
```

## 읽을 수 없을 때
날짜를 못 읽어 등록할 수 없으면 **등록하지 않고** 스레드로 되묻고, 원본 메시지에 ❓ 리액션을 단다. ❓도 처리 완료 표시이므로 같은 메시지를 매시간 다시 묻지 않는다.

```
날짜를 못 읽었습니다. "내일 15시 치과"처럼 적어주시면 등록합니다.
```

사용자가 새로 적은 메시지는 새 메시지이므로 다음 실행에서 처리된다.

## 금지
- 기존 이벤트 수정·삭제 — 등록만 한다
- 리액션이 달린 메시지를 다시 등록하는 것
- 제목을 요약하거나 말투를 고치는 것
- 메시지의 설명 부분을 버리는 것 — 리포트가 쪼갤 재료를 잃는다
- 리포트 루틴이 보낸 메시지를 일정으로 등록하는 것

# 쪼개기(decompose) 스펙

## 목적
그날의 Google Calendar 이벤트를 입력받아, (1) 고정 일정인지 유동 태스크인지 판별하고, (2) 유동 태스크는 실행 가능한 최소 논리 단위로 분해하며, (3) 각 단위의 예상 소요시간을 추정한다. 순서 배치는 이 단계에서 하지 않는다.

## 사용하는 config.json 필드
- `calendarId`: 이벤트를 조회할 캘린더.
- `timezone`: "그날"의 기준 시간대. 이 시간대의 00:00~24:00에 걸친 이벤트를 조회 대상으로 삼는다.

## 실행 절차
1. 이 저장소의 `config.json`을 `Read` 툴로 읽는다.
2. `calendarId`의 이벤트를 Google Calendar MCP(`list_events`, read-only)로 조회한다. 범위는 `timezone` 기준 오늘 하루다.
3. 아래 "판별 로직"·"분해 로직"에 따라 각 이벤트를 분류·분해하고 소요시간을 추정한다.
4. 결과를 [arrange](./arrange.md)의 배치 단계로 넘긴다.

## 판별 로직 (고정 vs 유동)
1. **컨벤션 우선**: 이벤트 제목이 `[TASK]` 프리픽스로 시작하면 무조건 유동 태스크로 취급한다.
2. **컨벤션이 없으면 판단**: 제목/설명을 보고 "정해진 시간에 참여해야 하는 일(회의, 예약, 통화 등)인가, 사용자가 알아서 처리하면 되는 작업인가"를 분류한다. 대표 키워드(회의/미팅/예약/통화/면접 → 고정, 작성/정리/준비/리뷰/기획 → 유동)를 참고한다.
3. 애매하면 **고정으로 분류**한다.
4. `fixed`로 분류한 이벤트는 분해하지 않고 원본 그대로 1개 항목으로 만든다.

## 분해 로직 (유동 태스크 → 실행 단위)
- 입력: 이벤트 제목 + 설명(있으면)
- 출력: 실행 가능한 문장 단위 리스트. "실행 가능하다"의 기준: 사용자가 그 문장만 보고 바로 무엇을 해야 할지 알 수 있어야 한다 (예: "프로젝트 A 작업" → "프로젝트 A 기획서 초안 작성", "프로젝트 A 팀원 피드백 반영").
- 분해 기준은 시간이 아니라 **의미 단위**다 — 더 쪼개면 의미가 없어지는 논리적 최소 작업까지만 쪼갠다. 원본 이벤트 하나가 N개 항목이 될 수 있다.
- 설명이 비어 제목만으로 분해 재료가 부족하면 **분해하지 않고 원본 그대로 1개 항목으로 반환**한다.
- 각 단위마다 예상 소요시간(분)을 따로 추정한다.
- 분해된 항목들의 소요시간 합이 원본 이벤트 길이를 넘거나 못 미쳐도 조정하지 않는다.

## 출력 형태 (배치 단계와의 계약)
각 항목은 아래 필드를 갖는다. 필드 구성은 고정이다.

- `title`: 실행 가능한 한 문장 (예: "보고서 초안 목차 작성")
- `kind`: `fixed` 또는 `task`
- `start` / `end`: `kind: fixed`에만. 원본 이벤트의 시작·종료 시각.
- `estimatedMinutes`: `kind: task`에만. 추정 소요시간(분).

## 금지
- 캘린더 쓰기 API 호출 (이벤트 생성·수정·삭제) — `list_events` read-only만 사용한다.

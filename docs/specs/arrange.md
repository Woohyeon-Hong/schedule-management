# 배치(arrange) 스펙

## 목적
[decompose](./decompose.md)가 만든 항목들(`kind: fixed | task`)을 받아, 유동 태스크(`task`)를 고정 일정(`fixed`) 사이의 빈 시간에 배치하고 Slack 리포트로 만든다.

## 사용하는 config.json 필드
- `workingHours`: 하루의 배치 가능 구간 (예: `"09:00-18:00"`). 이 밖의 시간에는 태스크를 배치하지 않는다.
- `priorityRule`: 유동 태스크의 순서를 정하는 기준(자연어 문장). 이 문장을 배치 기준으로 그대로 따른다.
- `onOverflow`: `workingHours` 안에 다 못 들어가는 태스크가 생겼을 때 처리 방식. `"push"`(기본) 또는 `"flag"`.
- `slackChannel`: 완성된 리포트를 보낼 채널.

## 배치 로직
1. `workingHours` 구간에서 고정 일정(`fixed`)의 `start`~`end`를 빼고, 남은 구간들을 빈 시간(gap)으로 잡는다.
   - 유동 태스크가 원본 캘린더에서 갖고 있던 시각은 **무시한다** — 그 시간도 gap이다. 태스크의 순서는 원본 시각이 아니라 `priorityRule`로 정한다.
   - `workingHours` 밖의 고정 일정(예: 저녁 약속)은 gap 계산에서 제외하되, 리포트에는 실제 시각 그대로 표시한다.
2. 유동 태스크(`task`)들의 전체 순서를 `priorityRule`에 따라 정한다.
3. 정해진 순서대로 앞의 gap부터 채운다 — 한 gap에 `estimatedMinutes` 합이 그 gap 길이를 넘지 않는 선까지 넣고, 넘치면 다음 gap으로 넘긴다.
4. 모든 gap을 채우고도 태스크가 남으면 `onOverflow`에 따라 처리한다.
   - `"push"`: 별도 표시 없이 순서 리스트 맨 뒤에 그대로 이어 붙인다.
   - `"flag"`: 남은 gap에 들어가지 않는 지점부터 구분선을 넣어 "여기부터는 오늘 안 들어갈 수도 있음"을 표시한다.

## 출력 형태 (Slack 리포트)
- 고정 일정: `start`~`end` **실제 시각**을 그대로 표시한다.
- 유동 태스크: **순서 번호 + 예상 소요시간만** 표시한다. 구체적 시각은 적지 않는다.

```
[오늘 하루 계획]

09:00-09:30 팀 주간 회의 (고정)

  1) 3분기 실적 데이터 정리 (45분)
  2) 보고서 초안 작성 (60분)

10:30-11:00 코드 리뷰 PR #482 (고정)

  3) PR #485 리뷰 (20분)
  4) 이메일 회신 (15분)
```

`onOverflow: "flag"`이면 남은 gap을 넘어서는 지점부터 구분선을 넣고, 번호는 이어서 매긴다.

```
  4) 이메일 회신 (15분)

  ──── 여기부터는 오늘 안 들어갈 수도 있음 ────

  5) 신규 기능 기획서 작성 (90분)
```

완성된 리포트를 `slackChannel`로 보낸다.

## 금지
- 고정 일정의 시각 변경
- 유동 태스크에 시각을 지어내 표시하는 것
- 태스크를 리포트에서 누락시키는 것 — `onOverflow` 어느 값에서도 전부 표시한다
- 캘린더 쓰기 API 호출 (재배치·수정 포함), 다음날 일정 변경
